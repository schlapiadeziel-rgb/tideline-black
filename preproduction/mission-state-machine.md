# 蓝潮货单：任务状态机规格

## 任务目标

让玩家在移动端完成一条 10–15 分钟的完整流程：从停车楼出发、接取货单、找到车辆、驾驶穿过潮汐街区、到达废弃水族馆、触发交货演出并返回停车楼。

## 状态定义

| 状态 | 进入条件 | 主要目标 | 退出条件 |
|---|---|---|---|
| `Intro` | 新任务开始 | 播放短引导镜头 | 玩家确认对话 |
| `Accepted` | 完成 NPC 对话 | 前往夜市车辆点 | 玩家进入车辆点范围 |
| `VehicleReady` | 车辆点触发 | 上车并前往水族馆 | 玩家进入车辆 |
| `Driving` | 玩家上车 | 沿导航路线驾驶 | 到达水族馆区域 |
| `Delivery` | 到达水族馆 | 下车并与后门交互 | 交互成功 |
| `Escape` | 交货演出结束 | 返回停车楼 | 玩家进入停车楼范围 |
| `Complete` | 返回停车楼 | 发放奖励并保存 | 玩家确认结算 |
| `Failed` | 超时或任务条件失败 | 显示失败原因 | 玩家选择重试 |

## 触发器规则

任务触发器必须有半径、朝向、可见标记和移动端容错。玩家距离目标 8 米时显示目标方向，距离 3 米时显示互动按钮。触发交互时不要求玩家精确对准像素级位置。

## 失败与恢复

首个切片不做永久失败。车辆损坏、玩家离开任务区域或超过时间时进入 `Failed`，保留最近检查点。玩家可以从当前阶段重试，也可以回到任务起点。应用切后台、系统来电或旋转锁定变化不得清空任务状态。

## 任务反馈

每次状态变化都必须同时反馈：HUD 任务标题变化、目标标记变化、音效变化和短文本提示。关键状态变化可以触发不超过 8 秒的镜头演出，但必须允许玩家跳过。

## 数据结构

任务使用数据资产保存阶段数组、目标点、导航规则、触发器、奖励、失败条件、对话引用和演出引用。逻辑代码只负责解释数据，不把坐标和文案硬编码在角色蓝图中。

## 验收用例

1. 新玩家不看说明也能找到第一个交互点。
2. 触屏误触不会跳过关键任务阶段。
3. 上车失败时能明确显示原因。
4. 到达水族馆后目标、镜头和交互提示不会互相遮挡。
5. 任务中断并重启后可从最近检查点恢复。
6. 完成任务后奖励只发放一次，重复进入不会重复结算。
